# Instrucciones de trabajo del proyecto

El usuario pidió el 10 de noviembre de 2026 guardar en GitHub los cambios que hagamos en Jarvis.

- Para cada cambio terminado, ejecutar las comprobaciones apropiadas, crear un commit descriptivo y enviarlo al remoto GitHub configurado.
- Conservar el historial; no hacer force-push ni reescribir commits publicados sin autorización explícita.
- Si falta autenticación o falla el envío, conservar el commit local e informar claramente de lo que queda pendiente. Nunca afirmar que un cambio está en GitHub sin comprobar el envío.
- No incluir credenciales, audio personal, modelos descargados ni entornos virtuales en Git.
- No avanzar de fase ni conectar acciones reales por el mero hecho de publicar el código; respetar el alcance autorizado por el usuario.
